# セブンハーツ スタッフ登録ツール（LINE公式アカウント連携）

LINE公式アカウントを友だち追加した人に、スタッフ登録に必要な情報をLINE上のフォームで入力してもらい、
Googleスプレッドシートに自動で保存するツールです。日雇いアルバイトとしての雇用を前提にしています。

## 全体の流れ

```
友だち追加
  └─ トークで「姓」→「名」の順に1問ずつ聞く
       └─ 「続きを入力する」ボタン → 登録フォーム（お名前は入力済み・面接の希望日時は第4希望まで）
            └─ 送信 → シート「スタッフ登録」に保存（ステータス：仮登録）

書類選考（担当者がシートのステータスを変える）
  ├─ 書類落選 → すぐに不採用通知を自動送信
  └─ 書類通過 → 応募者の希望日時を面接候補としてボタンで送信（ステータス：面接日程調整中）
       ├─ 応募者が日時を選ぶ → 面接確定（「面接日時（確定）」に記入）＋ 面接の受け方（Google Meet）を案内
       └─ 「どれも都合が合わない」→ 日程再調整（担当者にメール）

面接確定
  ├─ 1分以内 → Google カレンダーに予定を作り、Google Meet の会議を付ける（URLは「Google Meet URL」列）
  ├─ 面接当日の朝9時 → リマインド＋「Google Meet に参加する」ボタンを自動送信
  └─ 面接の時刻 → 「Google Meet に参加する」ボタンを自動送信 → 応募者が参加をリクエスト → 担当者が承認（20〜30分程度）

面接後（担当者がステータスを変える）
  ├─ 不採用 → 翌日の午前10時に不採用通知を自動送信
  └─ 採用 → 書類提出フォームの案内を自動送信（ステータス：書類依頼済）
       └─ 書類提出 → シート「労務情報」＋Googleドライブ（ステータス：書類提出済）→ 確認後「稼働可」

採用〜稼働可のスタッフ
  └─ スタッフ用リッチメニューを自動で表示 → 「マニュアル」ボタンでマンガのマニュアルを読める（だれがどこまで読んだかを記録）

稼働可のスタッフ（毎月）
  └─ 25日の午前10時 → 翌月のシフト提出フォームを自動送信
       └─ 出勤できる日を選んで送信 → シート「シフト提出」に保存
            └─ シート「シフト集計_2026年11月」に、日ごと・勤務エリアごとの出勤可能な人数を自動で作成
```

### 担当者の操作（シート「スタッフ登録」）

| やりたいこと | 操作 |
|---|---|
| 書類選考で通過させる | ステータスを「書類通過」にする。送る候補を絞るときは、先に「候補に送る（第1〜第4希望）」にチェック（チェックなしなら、過ぎていない希望日時をすべて送る） |
| 書類選考で落とす | ステータスを「書類落選」にする（通知はすぐ送られる） |
| 面接後に落とす | ステータスを「不採用」にする（通知は翌日の午前10時。急ぐときはメニュー「セブンハーツ > 不採用通知を今すぐ送る」） |
| 日程再調整の人と日時を決めた | トークで調整後、「面接日時（確定）」に日時（例：2026/10/12 14:00）を入れてから、ステータスを「面接確定」にする（確定の連絡と使い方が届き、当日のリマインドと参加用のボタンも自動で送られる） |
| 面接後に採用／不採用 | ステータスを「採用」／「不採用」にする |

スプレッドシートのメニュー「セブンハーツ > 不採用通知の送信予定を確認」で、誰にいつ送られるかを確認できます。
「候補日の送信日時」「リマインド送信日時」「通話案内の送信日時」「不採用通知の送信日時」の列で、送信済みかどうかを確認できます。
うまく送れなかった場合は「管理メモ」に理由が書き込まれます。

### Google カレンダーとの同期

面接日時が決まると（応募者がボタンで選んだとき・担当者が「面接確定」にしたとき）、1分以内に Google カレンダーへ予定が自動で入ります。

| シートでの変化 | カレンダー |
|---|---|
| 「面接確定」になった | 予定を作る（タイトル「面接（Google Meet）山田 花子 さん」、10分前に通知。説明欄に氏名・フリガナ・電話番号・希望エリアとシートのURL）。Google Meet の会議を付ける |
| 「面接日時（確定）」を書き換えた | 予定をその日時に動かす |
| 「日程再調整」にした・面接前に「不採用」などにした・日時を消した | 予定を消す（Google Meet URL も消える。日時が決まり直したら新しい会議を作る） |
| 面接が終わってから「採用」「不採用」にした | 予定は記録として残す |

- 登録先は、スクリプトを実行している人（setup を実行した人）のメインのカレンダーです。面接担当者用のカレンダーに入れたい場合は、そのカレンダーの「設定と共有 > カレンダーの統合 > カレンダー ID」をスクリプト プロパティ `CALENDAR_ID` に入れてください（setup を実行した人に、そのカレンダーの「予定の変更」権限が必要です）
- 予定の長さは30分です（面接は20〜30分程度。`INTERVIEW_MINUTES` で変更）。応募者への案内に書く長さは `gas/Interview.gs` の `INTERVIEW_LENGTH` で変えられます
- 予定には応募者の電話番号が入るため、カレンダーを一般公開したり、関係のない人に共有したりしないでください
- カレンダーに登録しない場合は `CALENDAR_ID` を `off` にします
- 予定をカレンダーで直接消すと、次の1分の自動処理で作り直されます。取り消すときは、シートのステータスや日時を変えてください
- 「カレンダー予定ID」「カレンダーに登録した面接日時」「Google Meet URL」の列は自動で記入されます（手で変えないでください）

### Google Meet での面接

面接は Google Meet（ビデオ通話）で行います（スクリプト プロパティ `INTERVIEW_METHOD` が空か `meet`）。
カレンダーの予定に Meet の会議を付けるので、Google カレンダーとの同期（上記）を使っていることが前提です（`CALENDAR_ID` を `off` にしないでください）。

**準備（最初に1回）**
1. Apps Script の左の「サービス ＋」で **Google Calendar API** を追加する（`gas/appsscript.json` を貼り直しても追加されます）
2. `setup` を実行する（シート「スタッフ登録」に「Google Meet URL」列が追加されます）
3. 新バージョンでデプロイし、`checkSettings` で「面接は Google Meet で行います」と出ることを確認する

**面接の流れ**
- 面接が決まると、1分以内にカレンダーの予定に Meet の会議が付き、URL がシートの「Google Meet URL」列に入ります（作成中の場合は数分かかることがあります）
- 応募者には、面接当日の朝9時のリマインドと、面接の時刻に「Google Meet に参加する」ボタンが届きます（確定時の案内で、Meet アプリを入れておくようお願いしています）
- 応募者への案内では、**iPhone はアプリなしで参加できる**（2026年6月から Safari などのブラウザで参加できるようになりました）、**Android は「Google Meet」アプリを前日までに入れておく**よう、機種ごとに書き分けています。どちらも Google アカウントは不要です
- 面接担当者は、カレンダーの予定から Meet に参加して待ちます。Googleアカウントのない応募者は「参加リクエスト」になるので、**「承認」** を押してください
- 何らかの理由で Meet の URL を作れなかった場合、面接の時刻に応募者へ「担当者から URL を送ります」と連絡し、担当者にメールで知らせます（エラーはシート「エラーログ」に記録されます）。
  その場合は、カレンダーの予定から Meet を開いてトークで URL を送ってください
- 面接担当者のアカウントが会社の Google Workspace で、組織外のゲストの参加を禁止している場合は、管理者に許可してもらってください

LINEコールに戻すときは、スクリプト プロパティ `INTERVIEW_METHOD` に `line` を入れます（下の「LINEコールの準備」を参照）。

### LINEコールの準備（`INTERVIEW_METHOD` が `line` のとき）

1. LINE Official Account Manager の「設定 > 通話」（または「LINEコール」）で **通話をオン**、通話の種類を **音声通話とビデオ通話**（ビデオ通話を受けられる設定）にする
2. 面接を担当する人のスマホに **LINE公式アカウントアプリ** を入れ、着信を受けられるようにしておく（ビデオ通話のため、カメラの使用を許可し、明るく静かな場所で応答してください）
3. 同じ画面に表示される **通話用のURL** をコピーし、Apps Script のスクリプト プロパティ `CALL_URL` に入れる
   （入れない場合は、面接の時刻に「トーク画面の通話ボタンから発信してください」という案内を送ります）

### 毎月のシフト提出と集計

- **毎月25日の午前10時**に、ステータスが「稼働可」のスタッフ全員へ、翌月のシフト提出フォームのボタンを送ります。
  25日より後に「稼働可」にした人にも、その月のうちに（1分以内に）送ります。送った月は「シフト提出の案内（送信済みの月）」列に入ります。
- スタッフはカレンダーで出勤できる日をタップして ○ にし、送信します（「すべて○」「土日祝を○」のボタンあり。時間の制限などは備考欄に）。
  カレンダーは **平日が白、土日祝が薄いオレンジ、土日祝が3日以上続く連休が赤** で表示されます（集計シートの行も同じ色）。
  祝日（振替休日・国民の休日を含む）は `gas/Shift.gs` で計算しています。祝日の法律が変わったときはここを直してください。
  月末まではトークで「シフト」と送ると何度でも変更できます（今月分は、過ぎた日は変更できません）。
- 提出内容はシート「シフト提出」に1人1か月1行で保存されます（1〜31日の列に ○／×）。
- シート **「シフト集計_2026年11月」**（月ごと）に、日ごと・勤務エリアごとの **出勤可能な人数** が提出から1分以内に作られます。
  - エリアはスタッフ名簿（シート「スタッフ登録」）の「希望エリア」を使います。複数のエリアを希望している人はそれぞれのエリアに数え、「合計（実人数）」列は重複なしの人数です
  - 人数のセルにカーソルを合わせると、出勤できる人の名前（メモ）が表示されます
  - 「エリアの登録人数」の行に、エリアごとの稼働可の人数を表示します。表の下に未提出のスタッフの一覧が出ます
  - 対象は、集計を作った時点でステータスが「稼働可」の人です。希望エリアやステータスを変えたときは、メニュー「セブンハーツ > シフト集計を更新（翌月分／今月分）」で作り直せます
- 25日を待たずに送りたいとき（動作確認など）は、メニュー「セブンハーツ > シフト提出の案内を今すぐ送る（翌月分）」を使います（送信済みの人には送りません）。
- **すでに運用中の場合の追加手順**：Apps Script に `Shift.gs` を追加して他のファイルも貼り直す → `setup` を実行（シート「シフト提出」と「スタッフ登録」の新しい列が作られます）→ 新バージョンでデプロイ。
  `setup` を実行するまでは、案内は送られません（`checkSettings` で確認できます）。
- 案内を送る日・時刻は `gas/Shift.gs` の `SHIFT_SEND_DAY`・`SHIFT_SEND_HOUR`、エリアの並び順は `gas/Options.gs` の `areas` で変更できます。

シート「登録途中」には、トークでお名前を答えたもののフォームをまだ送信していない人が表示されます（「回答中の質問」が「フォーム入力待ち」）。
フォームから登録すると、その人の行は自動で消えます。途中でやめた人へのフォローに使えます。
「氏名」（トークで答えたお名前。姓だけ答えた段階なら姓のみ）と「LINE表示名」の列で、誰の登録途中かがわかります。
この2列は、更新後に `setup` を1回実行すると「LINEユーザーID」のすぐ右に追加され、今いる人の分も埋まります。

登録途中の人には、リマインドを自動で送ります。

- 最後のやりとりから **1日後** と **3日後** に1回ずつ（10〜20時のあいだだけ。夜に1日たった人には翌朝10時に送ります）
- フォームの入力待ちの人には「スタッフ登録の途中です。あと少しで完了します（約2分）」と「続きを入力する」ボタン、お名前の途中の人には続きの質問を送ります
- 返事があったら回数を数え直し、また1日後・3日後に送ります。2回送っても反応がない人には、それ以上送りません
- 「リマインド回数」「リマインド送信日時」の列で確認できます
- メニュー「セブンハーツ > 登録途中の人にリマインドを今すぐ送る」で、全員に今すぐ送ることもできます（1時間以内に送った人は除く）
- 自動で送らないようにするには、スクリプト プロパティ `CHAT_REMINDER` を `off` にします
- リマインドは LINE公式アカウントの月の無料メッセージ数にカウントされます（1人1回1通）

トーク画面で次の言葉を送ると自動で返信します（それ以外のメッセージには返信しないので、担当者が手動でチャット対応できます）。

| 送信する言葉 | 返信内容 |
|---|---|
| 登録状況／ステータス | 現在のステータスと次にすること |
| 書類 | 書類提出フォーム（採用後のみ） |
| シフト | シフト提出フォーム（稼働可の人のみ。25日以降は翌月分、それより前は今月分） |
| マニュアル | スタッフマニュアル（マンガ）を開くボタン |
| 登録／応募 | 未登録の人：お名前の質問から開始（フォーム入力待ちの人にはボタンを送り直す） |
| 変更 | 登録済みの人：登録内容を変更するフォーム |
| やめる | 登録の途中で中断 |

## 集める情報

### ① 友だち追加の直後

| 場所 | 項目 |
|---|---|
| トーク | 姓、名（1問ずつ。姓の質問にフルネームを送った場合は自動で分けます） |
| 登録フォーム | 下の表のとおり |

登録フォームの質問（→ シート「スタッフ登録」に保存）

| 区分 | 質問 | 必須 |
|---|---|---|
| 基本情報 | お名前（トークの回答が入力済み）、フリガナ、生年月日、性別 | 必須 |
| 連絡先・住所 | 携帯電話番号、郵便番号（住所を自動入力）、都道府県、市区町村・番地、最寄り駅 | 必須 |
| | メールアドレス、建物名・部屋番号 | 任意 |
| 働き方の希望 | 職業、勤務できる曜日、希望エリア（大阪・兵庫・京都・滋賀・奈良・和歌山から複数選択） | 必須 |
| 免許・語学 | 普通自動車免許（あり／なし） | 必須 |
| | 日常会話ができる外国語 | 任意 |
| ユニフォーム・身だしなみ | 身長、靴のサイズ、服のサイズ、髪色 | 必須 |
| | お持ちの服装（黒スーツ・綿パン（黒）・チノパン（ベージュ）から複数選択）、自己PR・ご要望 | 任意 |
| アンケート | 何で当社を知りましたか？（indeed・タウンワーク・ショットワークス・タイミー・友達の紹介・会社HP・その他から1つ） | 必須 |
| 面接の希望日時 | 第1希望 | 必須 |
| | 第2〜第4希望 | 任意 |
| 同意 | 個人情報の取り扱いへの同意、反社会的勢力でないことの表明 | 必須 |

登録済みの人が「変更」と送ると、同じフォームで内容を変更できます（面接日時は変更時には表示しません）。

年齢による自動チェック（労働基準法）
- **中学校卒業前**（15歳に達した日以後の最初の3月31日まで）は登録できません。
- **18歳未満**はシートの「年齢による制限」列に注意書きが入ります（深夜22〜5時の勤務不可・年齢証明書の備え付けが必要）。

### ② 書類提出フォーム（採用後）→ シート「労務情報」＋ドライブ

| 区分 | 項目 |
|---|---|
| 本人確認 | 国籍、本人確認書類の種類と画像、顔写真 |
| 外国籍の方 | 在留資格、在留期間の満了日、在留カードの表と裏、資格外活動許可（「留学」「家族滞在」の場合） |
| 給与 | 銀行名、支店名、口座種別、口座番号、口座名義（カナ） |
| 緊急連絡先 | 氏名、続柄、電話番号 |
| 税・労務 | 他社での勤務の有無、他社に扶養控除等申告書を出しているか |
| その他 | 健康上の配慮事項（任意）、守秘義務・SNS投稿禁止への同意 |

- 「留学」「家族滞在」で資格外活動許可がない場合は提出できません。「就労可否の確認事項」列に、確認すべきこと（週28時間以内など）が入ります。
- **マイナンバーは集めていません。** マイナンバーカードは表面だけを受け取り、裏面（個人番号）はアップロード欄が出ないようにしています。

### 個人情報の取り扱いページ

`liff/privacy.html`（公開URL：`https://seven-hearts.github.io/LINE/liff/privacy.html`）。登録フォームの同意欄からリンクしています。
事業者名・所在地・代表者・問い合わせ先は、変更があればこのファイルを直してください。
別のページを使う場合は、スクリプト プロパティ `PRIVACY_POLICY_URL` にそのURLを入れてください。

選択肢（希望エリア、職業など）は `gas/Options.gs` で変更します。
登録フォームをすぐ表示できるよう、同じ選択肢を `liff/js/options.js` にも持たせています。`Options.gs` を変えたら
`npm run build:options` で `options.js` を作り直してください（ずれていると `npm test` が失敗します）。

## 案件の取り込みと LINE 配信

お客様から届いた手配依頼の文章を貼り付けるだけで、AI（Gemini または Claude）が読み取ってシート「案件一覧」にまとめます。
まとめた案件は、条件に合うスタッフに LINE で一斉に案内でき、スタッフはボタンを押すだけで応募できます。

```
依頼文を貼り付け（メニュー「セブンハーツ > 案件を取り込む（依頼文から）」）
  └─ AIが読み取り → 確認画面で直す → 「案件一覧」に追加（1日・1時間帯ごとに1行。売上などは自動計算）
       └─ メニュー「セブンハーツ > 案件をLINEで配信」→ 案件と送信先の条件を選んで配信
            └─ スタッフが日時のボタンを押す → シート「案件応募」に追加（応募人数も更新）
                 └─ 担当者が「状態」を「確定」／「見送り」にする → 本人に LINE で自動連絡
```

### 使い始める（すでにスタッフ登録ツールを運用中の場合）

1. Apps Script に `Jobs.gs`・`JobsApp.gs` と、HTML ファイル `JobImport`・`JobSend`・`DetailSend` を追加し、変更のあった `Code.gs`・`Sheet.gs`・`Webhook.gs`・`Interview.gs`・`Diagnostics.gs` を貼り直す
2. スクリプト プロパティに `GEMINI_API_KEY` を追加する（下の「AIの切り替え」参照）
3. 関数 `setup` を実行する（シート「案件一覧」「案件応募」「案件取込履歴」ができます。以前の形の「案件一覧」は、今の列の形に自動で直ります：服装と持ち物・集合担当者名と連絡先を別々の列に分け、「支払い」の列を消します）
4. 「デプロイを管理 > 鉛筆アイコン > 新バージョン」でデプロイし直す（応募ボタンを受け付けるため）
5. スプレッドシートを開き直すと、メニュー「セブンハーツ」に「案件を取り込む」「案件をLINEで配信」が出ます
6. `checkSettings` を実行し、「案件の読み取りは Gemini（…）を使います。APIキーは有効です」と出て、シートの列に ❌ がないことを確認する

### 取り込み

1. 「取引先名」を入れ（前に使った名前は候補に出ます）、依頼文をそのまま貼り付けて「読み取る」を押す（20〜60秒）
   - 1通に複数の案件が入っていても、案件ごとに分けて読み取ります
   - 案件の一覧と詳細が離れて書かれていたり、服装の続きが最後に書かれていたりしても、まとめて読みます
2. 読み取り結果を確認して、違うところを直す（日程の追加・削除もできます）。依頼文に書かれていないことは空欄のままです
3. 「シート『案件一覧』に追加」を押す。元の依頼文はシート「案件取込履歴」に残ります

「案件一覧」の列（前半の21列はこれまでの案件表と同じ並びです）

| 列 | 入る値 |
|---|---|
| 取引先名・タイトル・場所・仕事内容 | 依頼文から |
| ポジション | D（ディレクター）・AD（アシスタントディレクター）・ST（スタッフ）から選ぶ。取り込むときは ST（確認画面とシートで変えられます） |
| 日程・開始時間・終了時間 | 1日（同じ日に時間帯が複数あるときは時間帯ごと）に1行 |
| 曜日 | 日程から計算（「祝」と書かれていれば「月祝」など） |
| 休憩時間・実働時間 | 時間数（例：1、7.5）。休憩が書かれていなければ両方とも空欄 |
| 服装・持ち物 | 依頼文から（別々の列） |
| 単位・単価 | 単位は「時給」か「日給」から選ぶ。「拘束時間×¥1,600」なら「時給」「1600」、日当なら「日給」 |
| 売上 | 単価 × 時間（依頼文が「拘束時間×」なら勤務時間、「実働時間×」なら実働時間。「5h保証」などは保証時間以上）× 人数。取り込みの確認画面の「支払い方」で決まります（シートには残しません） |
| 交通費・食費 | 1人あたりの金額。食費が「支給あり」などで金額がないときはその文字 |
| 総支払額 | 売上 ＋（交通費 ＋ 食費）× 人数（お客様からの入金額の見込み） |
| 請求書 | 「未」で追加。「発行済」「入金済」に変えて使ってください |
| 売上計上月・入金予定月 | 日程の月と、その2か月後（末締め翌々月末払い）。株式会社Switch は1か月後。取引先ごとの例外は `gas/Jobs.gs` の `PAYMENT_TERM_EXCEPTIONS` に書きます |
| 人数・募集条件・集合時間・集合場所・住所・アクセス・集合担当者名・集合担当連絡先・備考 | 依頼文から（追加の列）。集合担当は名前と電話番号を別々の列に入れます |
| スタッフ向け給与・スタッフ向け交通費 | LINE で配信するときに表示する内容。給与は取り込みの確認画面か配信画面で入力（入れないと配信できません）。交通費は「全額支給」で統一 |
| 募集状況 | 「募集中」で追加。「募集終了」にすると配信の候補から外れ、応募ボタンも締め切りになります |
| 配信日時・配信人数・応募人数 | 自動で記入 |

単価・人数がわからない行は、売上・総支払額を空欄にします（推測しません）。

### LINE で配信

1. 「案件一覧」で配信したい案件の行を選んでから（選ばなくてもかまいません）、メニュー「案件をLINEで配信」を開く
2. 送る案件にチェックを入れ、**スタッフ向けの給与**（例：時給1,200円）を入れる（必須。取り込みのときに入れていれば入っています）。依頼文の単価（請求額）はスタッフには表示しません。交通費は「全額支給」で案内します
   - スタッフに届くカードには、タイトルのすぐ下に「💴 時給1,200円／🚃 交通費全額支給」が出ます
3. 送信先の条件を選んで「送信先を確認」→「〇人に配信する」
   - 対象のステータス（初期値は「稼働可」）、希望エリアが案件の都道府県と合う人、性別の指定がある案件はその性別の人、勤務できる曜日が合う人（任意）
   - 条件は案件ごとに判定し、一人ひとりには条件に合う案件だけをまとめて1通で送ります
   - 依頼文にある年齢の条件はスタッフに表示せず、送信先の絞り込みにも使いません（求人での年齢制限は法律で原則禁止されているため。お客様と確認してください）
   - 「送信先を確認」を押すと、条件に合う人の一覧（名前・ステータス・希望エリア・受け取る案件）が出ます。はじめは全員にチェックが入っていて、**チェックを外した人には送りません**。名前・フリガナで絞り込み、「表示中を全員選ぶ／外す」もできます
   - 案件や条件を変えたら、もう一度「送信先を確認」を押してください（一覧は選び直しになります）
4. スタッフには案件ごとのカードが届き、働ける日時のボタンを押すと応募できます（開始時刻を過ぎた日程・「募集終了」の案件は受け付けません）

### 応募への対応（シート「案件応募」）

| やりたいこと | 操作 |
|---|---|
| 仕事を確定する | 「状態」を「確定」にする（確定した日時と「詳細は後日お送りします」を本人に自動で送ります）。同じ人がすでに同じ日に確定している場合は確定にできず、元の状態に戻って「管理メモ」に理由が入ります（画面右下にもお知らせが出ます） |
| 確定した人に詳細を連絡する | メニュー「確定した人に詳細連絡を送る」（下の「詳細連絡」参照） |
| 当日の結果を記録する | 「勤務ステータス」を「出勤」「遅刻」「連絡欠勤」「無断欠勤」にする |
| お断りする | 「状態」を「見送り」にする（定員に達した旨を本人に自動で送ります） |
| 本人が辞退した | 「状態」を「辞退」にする（連絡は送りません。もう一度応募できるようになります） |

確定・見送りの連絡を送ると「結果の通知日時」に記入されます（2回は送りません）。
新しい応募があると、`ADMIN_EMAIL` にメールでお知らせします。

「状態」（B列）は担当者が選ぶ4つです。

| 状態 | 切り替わるとき |
|---|---|
| 応募 | スタッフが LINE の応募ボタンを押した |
| 確定 | 担当者が設定（確定の連絡を自動送信） |
| 見送り | 担当者が設定（お断りの連絡を自動送信） |
| 辞退 | 担当者が設定（連絡は送りません） |

確定した人の当日までの進み具合は、隣の「勤務ステータス」（C列）に入ります。

| 勤務ステータス | 切り替わるとき |
|---|---|
| 詳細送付済 | 詳細連絡を送った（自動） |
| 出発時間確認済 | スタッフから出発時間の返信が来た（自動） |
| 出発確認中 | 出発時間になり、出発確認を送った（自動） |
| 出発確認済 | 出発確認に「はい」と答えた（自動） |
| 出勤・遅刻・連絡欠勤・無断欠勤 | 担当者が設定 |

「日程」「開始予定時間」「終了予定時間」（G〜I列）は「案件一覧」と同じ値が入り、「案件一覧」で時間を変えると自動で反映されます（「案件応募」側を直接変えても、1分以内に「案件一覧」の値に戻ります）。

#### 手動で追加する

LINE 以外（電話など）で決まった人は、メニュー「セブンハーツ > 案件応募に手動で追加」から追加できます。

1. 日程を選ぶ（過ぎた日程も、2か月前まで選べます）
2. スタッフを選ぶ（「スタッフ登録」の人）か、「LINE 未登録の人」で名前・電話番号を入れる
3. 状態（確定・応募）を選んで「追加する」

- 枠ID・タイトル・日程・予定の時間・給与形態・単価は自動で入ります。「案件一覧」の応募人数も数え直します
- 登録済みのスタッフを「確定」で追加するとき、「LINE で確定の連絡を送る」にチェックがあれば、確定の連絡を送ります。チェックを外すと送りません（あとからも自動では送りません）
- 同じ日程にすでに入っている人や、同じ日にほかの日程で確定している人は追加できません
- 追加した行は、管理メモに「手動で追加」と入ります。請求書（freee）の計算にも含まれます

#### 実際の勤務時間と給与（J〜P列）

予定の時間とは別に、実際の勤務時間と給与を記録できます。

| 列 | 入力 | 内容 |
|---|---|---|
| 勤務開始時間・勤務終了時間 | 担当者 | 実際の時間（例：`9:00`、`18:15`）。日をまたぐ勤務もそのまま入れてください |
| 休憩時間 | 担当者 | 時間で `1`、`0.5`。`45分`、`1:00` でも入れられます（空欄は休憩なし） |
| 実働時間 | 自動 | 勤務終了 − 勤務開始 − 休憩 |
| 給与形態 | 自動（変更可） | 時給・日給。応募のときに「案件一覧」のスタッフ向け給与（例：時給1,200円）から入ります |
| 単価 | 自動（変更可） | 〃 |
| 給与額 | 自動 | 時給は 単価 × 実働時間（1円未満は四捨五入）、日給は 単価。勤務ステータスが連絡欠勤・無断欠勤なら0円 |

- 実働時間・給与額は、勤務時間・休憩時間・給与形態・単価・勤務ステータスを編集すると自動で計算し直します
- 給与額に交通費は含みません（交通費は「交通費（往復）」の列）

### 出発確認

出発時間になると、スタッフに次のメッセージを自動で送ります（勤務ステータスが「出発時間確認済」の人。「出発確認中」になります）。

```
おはようございます。出発時間になりました。

予定通り出発しましたでしょうか？
［はい］［いいえ］
```

- 「はい」→ 勤務ステータスが「出発確認済」になります
- 「いいえ」→ すぐに担当者（`ADMIN_EMAIL`）へメールします。スタッフには、今の状況をトークで教えてもらうよう返信します
- 送ってから10分たっても返信がない → 担当者へメールします（1回だけ）
- メールには、氏名・案件・日時・出発時間・電話番号が入ります。**`ADMIN_EMAIL` を設定しておいてください**（未設定だとメールは送られず、シート「エラーログ」に記録されます）
- 「はい」「いいえ」は、ボタンのほか文字で送っても受け付けます
- 「出発確認の送信日時」「出発確認の回答」「出発確認の回答日時」「担当者への通知日時」の列で確認できます
- 自動処理が止まっていたなどで出発時間を1時間以上過ぎた場合は、出発確認は送りません
- 出発時間が開始時刻より遅い場合（深夜・早朝の勤務）は、前日の出発とみなします

### 終了確認

勤務終了予定時間（「終了時間」）になると、状態が「確定」の人に次のメッセージを自動で送ります（勤務ステータスが「連絡欠勤」「無断欠勤」の人には送りません）。

```
お疲れ様です。勤務終了予定時間になりました。

本日の業務開始時間、終了時間、休憩時間
お弁当支給の有無、日払い希望かどうかを返信してください。
```

- スタッフが返信すると、内容が「案件応募」の「終了報告（返信内容）」に入り、次のお礼を自動で返します

```
返信ありがとうございます。本日もご勤務お疲れ様でした。

お気をつけておかえりください
```

- 返信を何通かに分けて送った場合（最初の返信から30分以内）は、「終了報告」に続けて足します（お礼は1回だけ）
- 終了確認を送ってから24時間を過ぎた返信は、自動では受け付けません（担当者がチャットで対応してください）
- 「終了確認の送信日時」「終了報告の日時」の列で確認できます
- 終了時間が開始時間より早い場合（日をまたぐ勤務）は、翌日の終了時刻に送ります

### 詳細連絡と、交通費・出発時間の返信

1. 「案件応募」で状態を「確定」にしておく（行を選んでから開くと、その案件が選ばれます）
2. メニュー「セブンハーツ > 確定した人に詳細連絡を送る」を開き、案件を選ぶ
3. 集合場所・集合時間・集合担当（名前と電話番号）・ギャランティ・昼食などを確認して直す（「案件一覧」の内容が入っています。集合場所・集合時間・集合担当・画像は「案件一覧」にも保存され、次に送るときの初期値になります）
   - 地図や集合場所の写真などの画像を3枚まで添付できます（「＋ 画像を選ぶ」。JPEG・PNG。自動で縮小します）。本文のすぐあとに届きます
4. 送る人を選び、プレビューを確認して「〇人に送る」。日程と時間は、一人ひとりが確定した日程だけが入ります

スタッフには次の2通が届きます。

```
ロハスミーツ高槻の詳細です。

内容をよく読んで交通費と出発時間をお調べください。

■タイトル
ロハスミーツ高槻
（業務内容・日程・場所・時間・集合場所・集合時間・集合担当・服装・ギャランティ・昼食・持ち物）
```
```
【ご返信のお願い】
「ロハスミーツ高槻」の交通費（往復）と出発時間を調べて、このトークに返信してください。
（返信の例）
交通費：1,060円
出発時間：7:30
```

- 詳細連絡を送ると、勤務ステータスが「詳細送付済」になります
- スタッフが返信すると、「案件応募」の「交通費（往復）」「出発時間」に自動で入り、両方そろうと「交通費・出発時間の返信日時」が入ります。出発時間が届くと勤務ステータスが「出発時間確認済」になります。スタッフには受け付けた内容を返信します
- 「1060円、7時半出発」のような書き方や、交通費と出発時間を別々に送っても読み取ります。片方だけのときは、もう片方を送るよう返信します
- 返信を待っている案件が複数あるときは、日程の早い案件から順に受け付けます
- 読み取れない文章（質問など）には自動で返信しないので、担当者がチャットで対応してください
- 送り直すと、前の返信は消えて、もう一度返信を待ちます
- 画面の「送る人」で、送信済み（返信待ち）・返信済み（金額と時間）を確認できます
- 添付した画像は、Google ドライブのフォルダ「セブンハーツ_詳細連絡の画像」に保存され、**「リンクを知っている全員」が見られる設定**になります（LINE で画像を送るのに必要なため）。個人情報が写った画像は添付しないでください。Google Workspace でリンクでの共有が禁止されている場合は、画像を添付できません

### AIの切り替え（Gemini の無料枠／Claude）

読み取りに使う AI は、スクリプト プロパティで選びます。`AI_PROVIDER` がなければ、APIキーが入っているほうを使います（両方あれば Gemini）。

| | Gemini（Google） | Claude（Anthropic） |
|---|---|---|
| 費用 | 無料枠の範囲なら無料 | 従量課金。案件1件の依頼文で10円前後、7件入りで50円前後 |
| APIキー | [Google AI Studio](https://aistudio.google.com/apikey) の「APIキーを作成」（クレジットカード不要） | [Claude Console](https://platform.claude.com/) の「API Keys」 |
| スクリプト プロパティ | `GEMINI_API_KEY` | `ANTHROPIC_API_KEY` |
| 読み取り方 | 依頼文1通を1回で読む | 案件を数えてから、案件ごとに並べて読む |
| 送った文章の扱い | **無料枠では、Google がサービスの改善に使うことがあります**（有料にすると使われません） | サービスの改善には使われません |

Gemini の無料枠について
- 1分・1日に使える回数に上限があります（モデルやGoogleの方針で変わります。[AI Studio](https://aistudio.google.com/) の「使用状況」で確認できます）。1日の上限に達すると「今日の無料枠を使い切りました」と表示され、翌日（日本時間の午後4〜5時ごろにリセット）まで使えません
- モデルは最新の Flash（`gemini-flash-latest`）を使います。変えるときは `GEMINI_MODEL` にモデル名を入れてください
- Gemini が混み合っている（「503」など）ときは、5秒・15秒待ってやり直します。それでもだめなときや、今日の無料枠を使い切ったときは、予備のモデル（軽量版の `gemini-flash-lite-latest`。無料枠も別に数えられます）で読み取ります。予備のモデルで読んだときは、確認画面にそう表示されます（読み取りの精度が少し下がることがあるので、よく確認してください）
  - 予備のモデルは `GEMINI_FALLBACK_MODELS` で変えられます（カンマ区切りで複数。`off` で切り替えない）
  - `ANTHROPIC_API_KEY` も入れておくと、Gemini がすべてだめなときに Claude で読み取ります（Claude の利用料がかかります）
- 依頼文には取引先の案件内容や現場担当者の連絡先が入るため、取引先との守秘義務の範囲で使ってください。気になる場合は Google AI Studio で課金を有効にする（有料枠）か、Claude に切り替えてください

Claude に切り替えるときは、`ANTHROPIC_API_KEY` を入れて `AI_PROVIDER` を `claude` にします（`GEMINI_API_KEY` は残したままでかまいません）。
読み取りの精度に差があると感じたら、同じ依頼文で両方を試して比べてください。

## スタッフマニュアル（マンガ）とリッチメニュー

お仕事の流れを縦スクロールのマンガで説明するページです。LINE のリッチメニューから開けます。

```
「マニュアル原稿」フォルダに画像を入れる（GitHub の画面からアップロード）
  └─ 自動で WebP に変換して小さくし、目次を作る（GitHub Actions：2〜3分）
       └─ マニュアルのページ https://seven-hearts.github.io/LINE/liff/manual/ が新しくなる

リッチメニューの「マニュアル」ボタン → マンガのページ
  ├─ 開いたとき・章の最後のページまで読んだとき → シート「マニュアル閲覧」に記録
  └─ 毎朝6時 → シート「マニュアル集計」に閲覧数をまとめる
```

**画像の入れ方・差し替え方は [`マニュアル原稿/README.md`](マニュアル原稿/README.md) にまとめています**（GitHub でフォルダを開くと表示されます）。

### 使い始める（すでにスタッフ登録ツールを運用中の場合）

1. Apps Script に `gas/Manual.gs`・`gas/RichMenu.gs` を同じ名前のファイルとして追加し、`Code.gs`・`Api.gs`・`Webhook.gs`・`Sheet.gs`・`Interview.gs`・`Diagnostics.gs` を貼り直す
2. 関数 `setup` を実行する（シート「マニュアル閲覧」「リッチメニュー設定」と、毎朝の集計のトリガーができます）
3. 「デプロイを管理 > 鉛筆アイコン > バージョン：新バージョン > デプロイ」でデプロイし直す（閲覧数を受け付けるため。忘れると記録されません）
4. スプレッドシートを開き直すと、メニュー「セブンハーツ」にマニュアルとリッチメニューの項目が増えます
5. GitHub の「Settings → Actions → General → Workflow permissions」が「Read and write permissions」になっているか確認する（画像の自動変換で使います）
6. [`マニュアル原稿/README.md`](マニュアル原稿/README.md) の手順で画像を入れる
7. 友だち全員用のリッチメニュー（Manager）にマニュアルのボタンを置く場合は、下の「リッチメニューの URL」を使い、スタッフ用は「スタッフ用リッチメニュー」の手順で作る

### マニュアルのページ

- 章ごとに目次があり、章の区切りに見出しと「次の章へ」ボタンが入ります。画像はすき間なく縦に並びます
- 前回読んだところを端末が覚えていて、次に開くと「前回の続きから読む」ボタンが出ます。読み終えた章には目次に「✓ 読んだ」が付きます
- ピンチで拡大できます。検索エンジンには載らない設定です（ただし URL を知っていればだれでも見られます）
- 章ごとの URL もあります（第2章なら `…/manual/#ch02`）。トークで「ここを読んでください」と送るときに使えます

### リッチメニューの URL

| 使う場所 | URL | 記録されること |
|---|---|---|
| 友だち全員用のリッチメニュー（LINE Official Account Manager で作る） | `https://seven-hearts.github.io/LINE/liff/manual/?from=menu` | 閲覧数（人数は端末の数） |
| スタッフ用リッチメニュー（下記。自動で設定） | `https://liff.line.me/<LIFF ID>/manual/?from=staffmenu` | 閲覧数と、**だれが**どの章まで読んだか |

- 友だち全員用のリッチメニューは、これまでどおり Manager の「リッチメニュー」で作り、ボタンのアクションを「リンク」にして上の URL を入れます
- トークで「マニュアル」と送ると、マニュアルを開くボタンが返ります（スタッフには LIFF の URL で返すので、だれが読んだかも記録されます）

### スタッフ用リッチメニュー

ステータスが「採用」「書類依頼済」「書類提出済」「稼働可」の人にだけ、別のリッチメニューを表示できます（Manager で作った友だち全員用のメニューより優先されます）。

1. リッチメニューの画像を作る（Canva などで）
   - 大きさ：**幅2500×高さ1686**（大）か **幅2500×843**（小）。PNG か JPEG で **1MB以下**
   - ボタンは画像を同じ大きさに等分して作ります。たとえば「横3×縦2」なら6等分（左上がボタン1、右へ2・3、下の段が4・5・6）。区切りに合わせて絵や文字を置いてください
2. 画像を Google ドライブに入れ、「共有 > リンクをコピー」で URL をコピーする（setup を実行したアカウントで開ける場所に置く）
3. シート「リッチメニュー設定」（setup で作られます）に入れる
   | 項目 | 入れるもの |
   |---|---|
   | 画像 | 手順2の URL |
   | 横のボタンの数・縦のボタンの数 | 画像の区切りの数（横1〜4・縦1〜3） |
   | メニューの文字 | トーク画面の下に出る文字（14文字以内） |
   | 最初から開く | 「はい」ならトークを開いたときにメニューが開いている |
   | ボタン1〜 | `マニュアル`（マニュアルを開く）／`https://…`（そのページを開く）／それ以外の言葉（その言葉をトークに送る。例：`シフト`・`登録状況`・`書類`・`変更`）／空欄（何もしない） |
4. メニュー「セブンハーツ > スタッフ用リッチメニューを作成・更新」を選ぶ → 確認の画面で「はい」
   - いまのスタッフ全員に表示されます。そのあとステータスが「採用」になった人には自動で表示し、「不採用」「退会」などに変えた人からは外します
   - 画像やボタンを変えたときも、同じメニューを選び直します（前のメニューは自動で消えます）
5. やめるときは、メニュー「セブンハーツ > スタッフ用リッチメニューをやめる」

リッチメニューの表示は、月の無料メッセージ数にカウントされません。

### 閲覧数の見方（シート「マニュアル集計」）

毎朝6時に自動で作り直します。すぐに見たいときは、メニュー「セブンハーツ > マニュアルの閲覧数を集計」を選びます。

| 表 | 内容 |
|---|---|
| 全体 | 開いた回数・閲覧した人数（累計と直近7日）、全章を読み終えた人数 |
| 章ごと | 章の最後のページまで読んだ人数と、閲覧した人数に対する割合（どこで読むのをやめているかがわかる） |
| スタッフ別 | ステータスが「採用」〜「稼働可」の人ごとに、開いた回数・最後に開いた日時・読み終えた章。**まだ開いていない人**もわかる |
| 開いた場所 | スタッフ用リッチメニュー・友だち全員用のリッチメニュー・トーク・URLから直接 |
| 日ごと | 直近30日の、日ごとの開いた回数と人数 |

- 人数は端末の数で数えます（同じ人がスマホとパソコンで開くと2人）。スタッフ用リッチメニューかトークのボタンから開いた人は、LINE のアカウントで数えます
- 目次から移動するときに通り過ぎた章は「読み終えた」に数えません（最後のページで1秒ほど止まると数えます）
- 元の記録はシート「マニュアル閲覧」にあります（5万行を超えると古いものから消えます）

## freee に請求書を作る

シート「案件一覧」の行から、freee会計の請求書（freee請求書）を**取引先とタイトルの組み合わせごと**に1枚ずつ作ります（同じ取引先でもタイトルが違えば別の請求書）。

1. メニュー「セブンハーツ > freee に請求書を作る」を開く
2. 請求する月（売上計上月）を選んで「内容を確認」→ 取引先・タイトルごとの明細・合計・支払期日が出ます
3. 作る取引先にチェックを入れて「freee に請求書を作る」
4. freee の「請求書」で内容を確認して、送付する（freee には **送付待ち** で作るので、自動で取引先に届くことはありません）

計算のしかた：

| 項目 | 内容 |
|---|---|
| 対象の行 | 選んだ月の行で、「請求書」が「未」（または空欄）、「freee請求書番号」が空欄のもの |
| 時給 | 単価 × 時間（開始〜終了。**休憩時間を含む**）× 人数（下を参照）。備考に「○時間保証」があれば、1人ずつその時間より短くしません |
| 日給 | 単価 × 人数 |
| 交通費・食費 | 1人あたりの金額 × 人数を、明細に別の行で入れます（税率10%） |
| 税 | 税抜（外税）・消費税10%・端数切り捨て。敬称は「御中」、入金方法は振込 |
| 請求日・支払期日 | 請求日は売上計上月の末日。支払期日は翌々月末（株式会社Switch は翌月末） |
| 件名 | 「2026年10月分 （タイトル）」。タイトルが空欄なら「2026年10月分 イベント運営業務」 |

- 作成すると、その行の「請求書」が「発行済」になり、「freee請求書番号」が入ります（二重に作りません）。作り直したいときは、freee で請求書を取り消し、シートの「請求書」を「未」に、「freee請求書番号」を空欄に戻してください
- 「案件応募」に **確定** した人がいる日程は、実際に働いた人（勤務ステータスが連絡欠勤・無断欠勤の人を除く）の人数と、1人ずつの **勤務開始時間〜勤務終了時間**（休憩を含む）で計算します
  - 時間が違う人は、明細を時間ごとに分けます（例：「10/8(木) 展示会運営 08:30〜18:00（9.5時間×2名）」「10/8(木) 展示会運営 09:00〜17:00（8時間×1名）」）
  - 勤務開始・終了時間が未入力の人は、予定の時間で計算し、確認画面に名前を表示します
  - 「案件一覧」の人数と違うときも、確認画面に表示します
- 「案件応募」に確定した人がいない日程（LINE 以外で手配した場合など）は、「案件一覧」の **人数** と予定の時間で計算します
- 単価・人数・単位・時間・取引先名が空欄の行があると、その取引先の請求書は作れません（確認画面に行番号が出ます）
- 取引先は、シートの「取引先名」と freee の取引先名（または正式名称）が同じものを使います（全角・半角や空白の違いは無視します）

#### 取引先名はプルダウンで選ぶ

メニュー「セブンハーツ > freee の取引先を読み込む」を実行すると、freee の取引先（使用停止のものを除く）がシート「取引先一覧」に入り、次のようになります（freee と連携したときにも自動で読み込みます）。

- 「案件一覧」の「取引先名」がプルダウンになり、一覧にない名前は入れられなくなります
- 「案件一覧」にすでにある取引先名は、freee の書き方にそろえます（例：「株式会社Switch」→「株式会社Ｓｗｉｔｃｈ」）。freee に見つからない名前は、画面に一覧で出ます
- 「案件を取り込む」の取引先名もプルダウンになります。依頼文から読み取った取引先名が一覧にあれば、自動で選ばれます
- freee に取引先を追加・変更したら、もう一度「freee の取引先を読み込む」を実行してください
- freee の請求書番号を「自動採番」以外にしていると作成できません。freee の請求書の設定で自動採番にしてください

### 使い始める（最初に1回だけ）

1. Apps Script に `gas/Freee.gs` を `Freee` という名前のスクリプトとして、`gas/FreeeInvoice.html` を「＋ > HTML」で `FreeeInvoice` という名前で追加し、`Code.gs`・`Jobs.gs`・`Sheet.gs`・`Interview.gs` を貼り直す
2. freee のアプリを作る：[freee アプリストアの開発者ページ](https://app.secure.freee.co.jp/developers) →「新しいアプリを作成する」
   - アプリ名は「セブンハーツ請求書」など。コールバックURLは `urn:ietf:wg:oauth:2.0:oob` のまま
   - 権限設定で、freee会計の「事業所」「取引先」の参照と、freee請求書の「請求書」の参照・更新にチェックを入れる
   - 表示された Client ID と Client Secret を、スクリプト プロパティ `FREEE_CLIENT_ID`・`FREEE_CLIENT_SECRET` に入れる
3. スプレッドシートを開き直し、メニュー「freee に請求書を作る」→「freee を開く」→ ログインして許可 → 表示された認可コードを貼り付けて「連携する」
   - 事業所が複数あるときは、請求書を作る事業所を選びます
   - 連携は、しばらく使わないと切れることがあります。そのときは画面の「連携し直す」から同じ手順でやり直してください

## セットアップ手順

### 1. LINE Developers でチャネルを用意する

[LINE Developers](https://developers.line.biz/console/) で、**同じプロバイダーの中に**次の2つのチャネルを用意します（プロバイダーが違うとユーザーIDが一致しません）。

1. **Messaging APIチャネル**：LINE公式アカウントに紐づいているもの
   - 「Messaging API設定」で **チャネルアクセストークン（長期）** を発行して控える
2. **LINEログインチャネル**：新しく作成
   - 「チャネル基本設定」の **チャネルID** を控える
   - 「LIFF」タブで LIFFアプリを追加
     - サイズ：Full
     - エンドポイントURL：手順4で公開するURL（`https://seven-hearts.github.io/LINE/liff/`）。手順4のあとで設定してもかまいません
     - Scope：`openid` と `profile` にチェック
     - 友だち追加オプション：On（Aggressive）
   - 作成された **LIFF ID** を控える
   - チャネルを「公開済み」にする

### 2. スプレッドシートと Apps Script を用意する

1. Googleスプレッドシートを新規作成する（例：「セブンハーツ スタッフ名簿」）
2. メニューの「拡張機能 > Apps Script」を開く
3. `gas/` の各ファイル（`Code.gs`、`Api.gs`、`Webhook.gs`、`Sheet.gs`、`Line.gs`、`Validation.gs`、`Options.gs`、`Chat.gs`、`Interview.gs`、`Diagnostics.gs`、`Jobs.gs`、`JobsApp.gs`、`Shift.gs`、`Manual.gs`、`RichMenu.gs`、`Freee.gs`）を、同じ名前のファイルとして作成し、内容を貼り付ける
   - `JobImport.html`・`JobSend.html`・`DetailSend.html`・`FreeeInvoice.html`・`ManualApply.html` は「＋ > HTML」で `JobImport`・`JobSend`・`DetailSend`・`FreeeInvoice`・`ManualApply`（`.html` は付けない）という名前で作成し、内容を貼り付ける
4. 「プロジェクトの設定」で「appsscript.json マニフェスト ファイルをエディタで表示する」をオンにし、`gas/appsscript.json` の内容を貼り付ける
5. 「プロジェクトの設定 > スクリプト プロパティ」に次の値を追加する

| プロパティ | 値 |
|---|---|
| `CHANNEL_ACCESS_TOKEN` | 手順1-1のチャネルアクセストークン |
| `LOGIN_CHANNEL_ID` | 手順1-2のチャネルID |
| `LIFF_ID` | 手順1-2のLIFF ID |
| `ADMIN_EMAIL` | 新規登録・面接日時の確定・日程再調整・書類提出を通知するメールアドレス（任意） |
| `INTERVIEW_METHOD` | 面接の方法（任意。`meet`：Google Meet（初期値）／`line`：LINEコール） |
| `CALL_URL` | LINEコールの通話用URL（任意。`INTERVIEW_METHOD` が `line` のときだけ使う。「LINEコールの準備」参照） |
| `WEBAPP_URL` | ウェブアプリのURL（任意。`checkSettings` がデプロイ済みの版を確認するのに使う） |
| `PRIVACY_POLICY_URL` | 自社のプライバシーポリシーのURL（任意だが推奨） |
| `MANUAL_URL` | スタッフマニュアルのURL（任意。初期値 `https://seven-hearts.github.io/LINE/liff/manual/`） |
| `STAFF_RICHMENU_ID` | スタッフ用リッチメニューのID（**自動で入ります。手で入れないでください**） |
| `GEMINI_API_KEY` | 案件の取り込みに使う Gemini の APIキー（無料枠あり。「AIの切り替え」参照） |
| `GEMINI_MODEL` | Gemini のモデル（任意。初期値 `gemini-flash-latest`） |
| `GEMINI_FALLBACK_MODELS` | Gemini が混み合っているときに使う予備のモデル（任意。初期値 `gemini-flash-lite-latest`。`off` で使わない） |
| `ANTHROPIC_API_KEY` | Claude で読み取る場合の APIキー（任意。「AIの切り替え」参照） |
| `CLAUDE_MODEL` | Claude のモデル（任意。初期値 `claude-opus-5-5`。`claude-sonnet-5-5` にすると費用はおよそ半分） |
| `AI_PROVIDER` | 読み取りに使う AI（任意。`gemini` か `claude`。なければ APIキーが入っているほう） |
| `PAYMENT_MONTHS_AFTER` | 入金予定月・請求書の支払期日が、売上計上月の何か月後か（任意。初期値 `2`。取引先ごとの例外は `gas/Jobs.gs` の `PAYMENT_TERM_EXCEPTIONS`） |
| `FREEE_CLIENT_ID`・`FREEE_CLIENT_SECRET` | freee に請求書を作るときに使う freee アプリの番号（任意。「freee に請求書を作る」参照） |
| `CALENDAR_ID` | 面接日時を登録する Google カレンダーの ID（任意。空ならメインのカレンダー、`off` なら登録しない） |
| `INTERVIEW_MINUTES` | カレンダーに登録する面接の長さ（分）（任意。初期値 `30`） |
| `CHAT_REMINDER` | 登録途中の人へのリマインド（任意。`off` で自動で送らない） |

6. エディタで関数 `setup` を選んで「実行」し、表示される権限をすべて許可する。次のものが自動で作られます。
   - シート「スタッフ登録」「労務情報」「登録途中」「案件一覧」「案件応募」「案件取込履歴」「シフト提出」「マニュアル閲覧」「リッチメニュー設定」
   - ドライブのフォルダ「セブンハーツ_スタッフ提出書類」
   - ステータス変更を検知するトリガーと、リマインド・シフト提出の案内などを送るトリガー（1分ごと）、マニュアルの閲覧数を集計するトリガー（毎朝6時）
   - Webhook用のトークン（実行ログに表示されます）
   - Google カレンダーへのアクセスの許可（面接日時を登録するため）
7. 「デプロイ > 新しいデプロイ > 種類：ウェブアプリ」を選ぶ
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
   - デプロイ後の **ウェブアプリURL**（`…/exec`）を控える

> コードを変更したときは「デプロイを管理 > 編集 > バージョン：新バージョン」で更新してください（URLは変わりません）。

### 3. Webhook を設定する

1. LINE Developers の Messaging APIチャネルの「Webhook URL」に次の形式で入力する
   `ウェブアプリURL?token=手順2-6で表示されたトークン`
2. 「Webhookの利用」をオンにする
3. [LINE Official Account Manager](https://manager.line.biz/) の「応答設定」で
   - Webhook：オン
   - あいさつメッセージ：**オフ**（このツールが友だち追加時のメッセージを送るため）
   - チャット：オンのままでOK（担当者が手動で返信できます）

### 4. フォームを公開する

1. `liff/js/config.js` の `LIFF_ID` と `GAS_URL`（手順2-7のウェブアプリURL）を書き換えてコミットする
2. GitHubリポジトリの「Settings > Pages」で、Source を「Deploy from a branch」、Branch を既定ブランチの `/ (root)` にして保存する
   - フォームのURL：`https://seven-hearts.github.io/LINE/liff/`（書類提出は `onboarding.html`、シフト提出は `shift.html`。LIFFは1つで共用します）
   - リポジトリを非公開にする場合は、Netlify（Publish directory を `liff` にする）でも無料で公開できます
3. このURLを、手順1-2のLIFFの「エンドポイントURL」に設定する

### 5. 動作確認

1. 自分のスマホで公式アカウントをいったんブロックし、ブロックを解除する（友だち追加と同じ扱いになります）
2. お名前を送り、届いたボタンからフォームを送信して、シート「スタッフ登録」に1行追加されることを確認する
3. その行のステータスを「採用」に変えると、書類提出のボタンが届くことを確認する

## 運用時の注意

- **シートとドライブのフォルダは、必要な担当者以外に共有しないでください。** 特に「労務情報」シートと提出書類のフォルダには、口座情報や身分証の画像が入ります。共有する場合は「スタッフ登録」シートだけを別のスプレッドシートに `IMPORTRANGE` で取り込むなどしてください。
- 列の見出しの文字は変更しないでください（列の追加や並べ替えは問題ありません）。管理用の列は「管理メモ」「書類確認者」「書類確認日」を使えます。
- 登録のお礼、面接候補、当日のリマインド、通話ボタン、不採用通知、書類提出の案内・お礼は、LINE公式アカウントの月の無料メッセージ数にカウントされます（1人あたり最大6通程度）。
  稼働可のスタッフには、毎月のシフト提出の案内が1人1通かかります。友だち追加時の質問、面接日時を選んだときの確定連絡、キーワードへの返信は、無料の応答メッセージです。
- 退会したスタッフの個人情報は、保存期間を決めて削除してください（賃金台帳などの法定の保存期間に注意）。

## うまく動かないとき

Apps Script エディタで関数 `checkSettings` を選んで「実行」すると、スクリプト プロパティ・チャネルアクセストークン・
Webhook URL・シートの列・トリガー・デプロイ済みの版を点検し、問題のある項目と直し方を実行ログに表示します。

フォーム・LINE・自動送信で起きたエラーは、シート「エラーログ」に記録されます（`checkSettings` でも最近の10件を表示します）。
フォームは、電波の途切れやGoogle側の一時的なエラーのときは自動で2回までやり直し、ログインの期限が切れたときは自動でログインし直します。

**コードを貼り直したら、必ず「デプロイを管理 > 鉛筆アイコン > 新バージョン」でデプロイし直してください。**
フォームの画面（GitHub Pages）は自動で新しくなるため、デプロイし忘れると画面と Apps Script の項目が食い違い、登録がシートに保存されません。
