# スタッフマニュアルの画像の入れ方

このフォルダに、マニュアルのマンガの画像を **章ごとのフォルダ** に分けて入れます。
入れると2〜3分で自動的に変換され、マニュアルのページ（https://seven-hearts.github.io/LINE/liff/manual/ ）が新しくなります。

パソコンのブラウザ（Chrome か Edge がおすすめ）で行ってください。スマホの GitHub アプリからは画像を入れられません。

---

## 名前の付け方（ここだけ守ってください）

```
マニュアル原稿/
├─ 01_はじめに/          ← 「数字_章の名前」
│   ├─ 01.png             ← ページの順番の数字
│   ├─ 02.png
│   └─ 03.png
├─ 02_出勤前の準備/
│   ├─ 01.png
│   └─ 02.png
├─ 03_現場での動き/
└─ 04_困ったとき/
```

| もの | 付け方 | 例 |
|---|---|---|
| 章のフォルダ | `数字_章の名前`。数字の順に第1章・第2章…と並ぶ。`_` の後ろが目次に出る章の名前 | `01_はじめに` |
| ページの画像 | `数字.png`（または `.jpg`）。数字の順に上から並ぶ | `01.png`、`02.png` |
| 下書き（まだ公開しない章） | フォルダ名の先頭に `_` を付ける | `_05_研修` |

- 数字は `01`、`02` のように2桁にそろえると、見たときに順番がわかりやすくなります（`1`、`2`、`10` でも正しく並びます）
- 画像の大きさは今のもの（幅1024×高さ1536の PNG）のままで大丈夫です。自動で小さく（WebP 形式に）変換されるので、スマホでもすぐ表示されます
- 1枚の画像は 25MB 以下にしてください（GitHub の画面から入れられる上限）

---

## はじめて画像を入れるとき・章を追加するとき

1. https://github.com/seven-hearts/LINE を開く
2. ファイルの一覧から **「マニュアル原稿」** フォルダをクリックして開く
3. 右上の **「Add file」→「Upload files」** を押す
4. パソコンで作った **章のフォルダ（例：`01_はじめに`）を、フォルダごと** 画面にドラッグ＆ドロップする
   - 4章分をまとめて入れるときは、4つのフォルダを選んで一度にドラッグできます
   - フォルダごと入れると、フォルダの名前もそのまま入ります。画像だけをドラッグすると章に分かれないので注意してください
5. 一覧に `01_はじめに/01.png` のように表示されたことを確認し、下の緑のボタン **「Commit changes」** を押す
6. 上の **「Actions」** タブを開き、「マニュアルの画像を変換」の横が **緑のチェック ✅** になるまで待つ（2〜3分）
   - 黄色の丸 🟡 は変換中、赤い × ❌ は失敗です（「うまくいかないとき」を見てください）
7. さらに1〜2分待ってから、スマホでマニュアルを開いて確認する
   - 古いままのときは、ページを閉じて開き直してください

## ページを差し替えるとき（絵や文字を直したとき）

1. 「マニュアル原稿」→ 直したい章のフォルダ（例：`02_出勤前の準備`）を開く
2. 「Add file」→「Upload files」で、**同じ名前の画像**（例：`03.png`）をドラッグ＆ドロップする
3. 「Commit changes」を押す → あとは上の手順6・7と同じ

同じ名前で入れると、前の画像と入れ替わります。

## ページを最後に追加するとき

章のフォルダを開き、続きの番号の画像（例：`06.png`）を「Upload files」で入れます。

途中にページをはさみたいときは、その章の画像の番号をパソコンで付け直してから、「章をまるごと入れ直す」の手順で入れ直すのが簡単です。

## 章をまるごと入れ直すとき・章を消すとき

GitHub の画面では、フォルダをまとめて消せません。画像を1枚ずつ消します。

1. 章のフォルダを開き、消したい画像（例：`01.png`）をクリックする
2. 右上の **「…」→「Delete file」** を押し、「Commit changes」を押す
3. その章の画像をすべて消すと、フォルダもなくなります
4. 入れ直すときは、「はじめて画像を入れるとき」の手順でフォルダごと入れます

章の名前や順番を変えたいときも同じです（新しい名前のフォルダで入れて、古いフォルダの画像を消す）。
数が多くて大変なときは、[GitHub Desktop](https://desktop.github.com/)（パソコンのアプリ）を使うと、パソコンのフォルダと同じ感覚でまとめて名前の変更や削除ができます。

## うまくいかないとき

**「Actions」タブで赤い × になった**

- × の付いた行をクリック →「build」→ 赤くなっている手順を開くと、理由が日本語で表示されます
  - 「画像を読み込めませんでした：02_出勤前の準備/03.png」→ その画像が壊れています。保存し直して入れ直してください
- 「Permission denied」や「403」と出る場合は、変換した画像を保存する許可がありません。
  リポジトリの **Settings → Actions → General → Workflow permissions** を **「Read and write permissions」** にして「Save」を押し、
  「Actions」タブの「マニュアルの画像を変換」→ **「Run workflow」** でやり直してください

**緑のチェックなのに、マニュアルが新しくならない**

- 公開（GitHub Pages）まで、さらに数分かかることがあります。「Actions」タブに「pages build and deployment」が出て、それも緑のチェックになれば公開済みです
- LINE の中のブラウザが古い表示を覚えていることがあります。ページを閉じて開き直してください

**目次の章の名前がおかしい**

- フォルダ名が `数字_章の名前` になっているか確認してください（`_` は半角のアンダーバー）

## 参考：自動で行われていること

- このフォルダに画像が入ると、GitHub Actions（`.github/workflows/manual.yml`）が `scripts/build-manual.js` を実行します
- 画像を WebP 形式に変換して `liff/manual/pages/` に入れ、目次のデータ `liff/manual/manual.json` を作り直します（この2つは手で変えないでください）
- 変換後の画像の名前には、画像の内容から作った記号が付きます。画像を差し替えると名前も変わるので、スマホに古い画像が残り続けることはありません
- 閲覧数は、スプレッドシートのシート「マニュアル集計」で確認できます（リポジトリの README.md「スタッフマニュアル（マンガ）とリッチメニュー」）
